# 风格五维标准与容差（icon-freedom）

## 为什么是"对规格打分"而不是"彼此比较"

让 agent 判断"这几个图标像不像"是相对判断，越比越糊。正确做法是先定一条
**项目风格规格**（`.icons/spec.json`，标尺取自主干库），所有候选各自和规格比。
跨库候选因此天然可比，参照集（已入库图标）再兜一层视觉标尺。

## 五维详表

| # | 维度 | 测法 | 容差/处置 |
|---|------|------|-----------|
| 1 | 线性 vs 面性 | 解析 SVG：描边元素带 `stroke` 色 = 线性；纯 `fill` = 面性；两者并存 = 混合 | 硬指标。与规格不符 → REJECT（不可自动转换）；混合 → REJECT |
| 2 | 笔画粗细 | `stroke-width / max(viewBox宽,高)` 归一化比值；取中位数抗异常值 | 与规格偏差 >20% → FIXABLE（normalize 按 `stroke_px/grid` 改写） |
| 3 | 圆角 | `stroke-linecap` / `stroke-linejoin` 取众数；缺省视为 butt/miter | 不一致 → FIXABLE（统一改写为 spec.caps） |
| 4 | 栅格与留白 | viewBox 尺寸（24/512/1024 各库不同）+ 缩放居中 | 尺寸不符 → FIXABLE（重缩放 + 居中）。**留白比例程序不判**，视觉复审把守 |
| 5 | 墨水密度 | 渲染 64×64 位图，非透明像素占比（线性典型 10~20%，面性 40~60%） | **仅报告不判罚**（需 cairosvg+PIL，可选）；视觉复审把守 |

补充硬淘汰：`url()` 渐变/图案填充、≥2 种颜色（彩色图标）→ REJECT。
内嵌 `<style>` 的 SVG → 提示人工复核（CSS 类选择器属性解析不全）。

## 视觉复审（agent 亲自看图）把守什么

源码测不出但眼睛一看就知道的：

- 造型语言：几何规整 vs 手绘有机感
- 视觉重心偏移、图形歪斜
- 留白节奏（图形占栅格的比例观感）
- 细节密度（一个图标塞 20 个细节 vs 参照集的克制程度）

产出要求：挑出前 3~5 个，每个落选者写一句话理由（例："笔画视觉重量比参照轻一档"）。

## 用户圈选（唯一人工环节）

- 展示 `render_sheet.py` 的 html（参照区金色框当标尺，点选导出 JSON）。
- 用户也可口头描述（"第 2 个，但想要更圆润的"）→ agent 按方向重搜一轮。
- 结论追加 `.icons/decisions.md`：日期 / 需求 / 选中 / 淘汰理由。
- 用户明示"你自己定"时可跳过，但决策必须记档。

## 规范化能救什么、救不了什么

- 能救（icon_normalize.py 全自动）：栅格重缩放、居中、stroke-width 改写、linecap/linejoin 统一、去色 currentColor、属性拍平。
- 救不了：线性↔面性互转（要重画）、彩色→单色的语义取舍（要设计判断）、留白/造型（视觉复审把守）。

## 多端细则（uni-app H5/小程序/APP）

- 产物三格式：woff2（现代）+ woff（过渡）+ ttf（老 webview 兜底），css `@font-face` 全声明。
- 小程序不认外链 css：**永远本地打包**；`--base64` 把 woff2 内嵌 css 可再省一个字体请求。
- class 命名空间：统一 `{prefix}-{name}` 且 prefix 全项目唯一，防组件库（uv-icon 等）字体族冲突。
- 颜色一律 currentColor：主题色由外层 CSS 变量/主题类驱动，换肤零改动。

## 检索源优先级与风险

1. 主干库 npm 包（Remix/Tabler 等）：SVG 质量最高、天然合规，首选。
2. iconfont.cn 社区 MCP：中文检索方便；**无官方 API**，登录态属逆向（Cookie/Playwright），
   验证码会卡自动登录，Cookie 注入更稳；任何"写入我的项目/建项目"能力官方都没有，勿承诺。
3. 浏览器人工辅助 + 定制 SVG 自传：行业特有概念（本行业业务词汇任何现成库都没有）的最终兜底。
